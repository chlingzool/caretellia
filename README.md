# Caretellia

**Caretellia** 是一款使用 Tauri 2、Vue 3 和 Vite 构建的信件与明信片创作工具。你可以设计信封、明信片和信纸，在应用中预览，并保存为 CLC 或 HTML 文件。

## 功能

### 创作与个性化

- 提供信封、明信片和单面信纸版式；信纸正文和明信片背面支持富文本编辑。
- 自定义字体、字号、颜色、边框、图片和邮票，也可以使用本机字体。
- 信纸支持添加贴纸，并可拖动、缩放和旋转；贴纸布局会随信件保存。
- 通过模板库浏览信封、明信片、信纸版式和文案。
- 信封预览按“打开信封、抽出信纸”的顺序展开，并支持收回。
- 编辑预览支持调整大小；窄屏界面提供折叠菜单。Android 端适配系统返回键、安全区域和触控操作，表单输入与贴纸控件也针对触屏优化。

### 保存、导出与导入

- **CLC 是 Caretellia 的信件文件格式**，默认导出格式为 `.clc`，用于保存信件内容和样式。
- 可从历史信件导入 CLC。导入时会检查格式版本、数据长度、SHA-256 摘要和信件字段；历史缓存也以压缩的 CLC 数据保存在本机。
- 编辑时选择“另存为”，可指定保存位置和 **CLC 或 HTML** 格式。快捷导出仍提供默认 CLC 导出，也可从导出菜单选择 HTML。
- 导出的信件居中显示；HTML 文件支持浅色、深色或跟随系统主题，并适配移动屏幕。

### 查看信件与管理历史

- 首页的“查看信封”用于浏览已保存的历史信件，或打开本地 CLC 文件预览；打开的文件不会自动加入历史信件。
- 桌面安装包会将 `.clc` 注册为 Caretellia 可打开的文件类型；双击 CLC 文件即可在“查看信封”中预览。
- 查看页的“历史信件”和“最近查看”列表可分别折叠。历史信件的删除仍统一在“历史信件”页面进行，查看页不提供删除历史信件的操作。
- 最近查看数量可在设置中限制，默认 **10 封**，可选 5、10、20 或 30 封。文件已不存在时会显示占位记录，可从最近查看中移除。
- 桌面应用会检查最近查看的本地文件是否仍存在；浏览器开发运行时会保存导入文件的本机浏览器副本。

### 应用设置

- 界面语言支持简体中文、英文和跟随系统。
- 支持深色/浅色模式、界面字体与字号，以及 HTML 导出主题设置。
- 设置中的“更新”可检查 GitHub 已发布的稳定版；桌面端支持签名校验后在应用内下载和安装。
- 应用数据保存在本机，不会上传到网络。

## 开发环境

- Node.js 和 npm
- Rust 工具链（包含 Cargo）
- 当前操作系统所需的 Tauri 2 开发依赖

安装 Tauri 所需的系统依赖前，请参阅 [Tauri 2 前置条件文档](https://v2.tauri.app/start/prerequisites/)。

## 运行与构建

在仓库根目录安装前端依赖并启动桌面开发模式：

```bash
npm install
npm run tauri dev
```

检查 TypeScript 并构建前端资源：

```bash
npm run build
```

构建 Tauri 桌面应用及当前平台可用的安装包：

```bash
npm run tauri build
```

## 更新项目版本号

在项目根目录运行以下命令，并按提示输入新的 `major.minor.patch` 版本号：

```bash
npm run verup
```

脚本会先显示当前版本，再同步更新 npm、Tauri 和 Cargo 的项目版本及 lockfile，不会更改依赖版本。随后会将这些版本文件加入暂存区、显示全部暂存改动，并在你输入 `PUSH` 确认后提交并推送到 `dev`，再创建一个指向 `release` 的 PR；PR 需要手动合并。已有的暂存改动也会包含在这次提交中；版本文件会整文件暂存，因此其中已有的未暂存改动也会一并包含。其他文件的未暂存改动会留在本地。PR 标题留空时使用提交信息，描述留空时不附描述。

使用此流程需要安装 Git、Python 和 GitHub CLI (`gh`)，并完成 GitHub CLI 登录。脚本要求当前位于 `dev` 分支，且本地 `dev` 与 `origin/dev` 同步；若已有从 `dev` 到 `release` 的开放 PR，脚本会停止以避免创建重复 PR。

## 配置应用内更新

桌面版从 GitHub 最新的已发布稳定版检查更新。若要发布可在应用内安装的更新，先生成 Tauri updater 签名密钥：

当前仓库的公钥已配置在 `src-tauri/tauri.conf.json`；与之配对的私钥在首次配置时生成并保存在开发机的 `~/.tauri/caretellia.key`，不会提交到仓库。将该私钥文件的完整内容添加到 GitHub 仓库的 Actions secrets，名称为 `TAURI_SIGNING_PRIVATE_KEY`。当前密钥未设置密码；若以后生成带密码的密钥，还需添加 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。请妥善备份并长期使用同一把私钥；丢失或更换密钥后，已有安装无法验证后续更新。若必须换钥，还需同步替换配置中的公钥，并要求已有用户手动安装一次新版本。

`tauri-action` 会为签名更新生成 Release 资源。工作流创建的 Release 是草稿，必须在 GitHub 上正式发布后，应用才会从稳定版更新地址获取到它。包含更新器的首个版本需要用户手动安装一次；之后才能使用应用内更新。

## 移动端构建

在 GitHub Actions 的 `mobile-build` 工作流中手动运行，可构建并下载 Android arm64 调试 APK 和 iOS arm64 Simulator 调试应用。工作流会在 CI 中初始化 Tauri 移动工程；构建产物保留 7 天。

Android APK 可安装到 arm64 Android 设备用于测试；iOS 产物仅用于 Simulator。安装到实体 iPhone 或发布到 App Store 仍需 Apple 开发者签名证书和 provisioning profile，本工作流不处理签名或商店发布。
